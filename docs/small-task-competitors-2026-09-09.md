# Competitor mechanisms relevant to small Scopelet tasks (2026-09-09)

Checked current upstream heads: Headroom `e67b3c8a29443a60d6b0018fb22f525c5cd7e709`, RTK `8e9aa04cb2afb189747fac4e36bec2254ddd0564`, and Caveman `15581d14007fd01fb3f132016741962f34936ca2`.

## Headroom

* **Cache-aware placement of small steering text.** Headroom appends its verbosity instruction at the end of the system prompt specifically to preserve the cached prefix; its tests also preserve an Anthropic block carrying `cache_control` and make steering idempotent. This is a cheap analogue for Scopelet: if a tiny instruction or metadata suffix is needed, append it after stable content and avoid rewriting the prefix. Sources: [README output shaping](https://github.com/headroomlabs-ai/headroom/blob/e67b3c8a29443a60d6b0018fb22f525c5cd7e709/README.md#output-token-reduction), [output steering tests](https://github.com/headroomlabs-ai/headroom/blob/e67b3c8a29443a60d6b0018fb22f525c5cd7e709/tests/test_output_steering.py).

  The exact steering helper is byte-stable and sentinel-based: it appends or replaces one block, returns no change when already applied, and handles Anthropic system blocks, OpenAI chat system/developer messages, and Responses `instructions`. This matters for short edits because repeated prompt rewriting would cost more than the intended saving. Source: [steering implementation](https://github.com/headroomlabs-ai/headroom/blob/e67b3c8a29443a60d6b0018fb22f525c5cd7e709/headroom/proxy/output_steering.py).

* **Explicit no-op reasons and a size floor.** Headroom reports `too_small (< 500 tokens)`, provider-cache-frozen prefixes, passthrough token-counting, and no compressible content as separate reasons. That supports a deterministic small-output fast path and useful diagnostics rather than forcing a transform. This is source behavior; the README's 21–57% figures are seeded benchmark token counts, not universal savings. Source: [MCP stats reason mapping](https://github.com/headroomlabs-ai/headroom/blob/e67b3c8a29443a60d6b0018fb22f525c5cd7e709/headroom/ccr/mcp_server.py).

* **Immutable recovery handles.** The MCP compressor stores the original and returns a hash/marker that can retrieve it later; unchanged file reads can return a roughly five-token marker after a hash check. This is potentially useful for repeated large inputs, but the marker only helps when the model already has the content or can retrieve it. Source: [file-cache implementation](https://github.com/headroomlabs-ai/headroom/blob/e67b3c8a29443a60d6b0018fb22f525c5cd7e709/headroom/ccr/mcp_server.py#L980-L1045).

## RTK

* **Deterministic type/command filters.** RTK routes commands to four simple operations: remove noise, group, truncate, and deduplicate. It has explicit passthrough commands and says built-in agent `Read`/`Grep`/`Glob` tools bypass the hook. Scopelet could use the same routing idea for tiny edits: only invoke a specialized reducer when a detector predicts enough removable repetition; otherwise emit original bytes. Sources: [filter strategy](https://github.com/rtk-ai/rtk/blob/8e9aa04cb2afb189747fac4e36bec2254ddd0564/README.md#how-it-works), [supported-tool scope](https://github.com/rtk-ai/rtk/blob/8e9aa04cb2afb189747fac4e36bec2254ddd0564/README.md#supported-ai-tools).

* **Recovery on failure/truncation plus passthrough quality metrics.** Failed commands store full unfiltered output and expose a recall handle. RTK telemetry tracks top zero-savings commands, parse failures, and low-savings commands, which is a useful feedback loop for widening or removing weak filters. Its reported token counts are only `bytes / 4` estimates; README reductions are bash-output reductions, not billed or full-session savings. Sources: [recovery/configuration](https://github.com/rtk-ai/rtk/blob/8e9aa04cb2afb189747fac4e36bec2254ddd0564/README.md#configuration), [telemetry schema](https://github.com/rtk-ai/rtk/blob/8e9aa04cb2afb189747fac4e36bec2254ddd0564/docs/TELEMETRY.md).

## Caveman

* **Detector then structure-specific reducer.** Caveman's `detect()` selects JSON/log/code/diff/search/text handling; its table describes preserving keys, errors, signatures, changed lines, and diagnostic hits. `contextwindow.Pack()` then fits candidates to a budget using relevance, recency, and error signals while returning original order. Scopelet already has JSON/JSONL structure handling and repeated-row compaction in `src/compress.rs`; treat those as existing coverage, not new work. The transferable lesson is detector-driven routing plus recovery, not copying lossy rules. Source: [engine description](https://github.com/JuliusBrussee/caveman/blob/15581d14007fd01fb3f132016741962f34936ca2/README.md#what-the-engine-keeps-by-payload-type), [Scopelet compressor](../src/compress.rs).

* **Response-style rules guard meaning while cutting ceremony.** Caveman's skill drops filler, pleasantries, hedging, and articles where grammar allows; keeps technical terms, commands, identifiers, exact errors, numbers, and code blocks; targets short sentences; and says never add words merely to sound terse. It recommends one idea per sentence with imperative wording and restores normal prose when compression would create ambiguity. Source: [Caveman skill](https://github.com/JuliusBrussee/caveman/blob/15581d14007fd01fb3f132016741962f34936ca2/skills/caveman/SKILL.md). For Scopelet, existing user requirements still take priority; the live Fable check shows why response length should be measured with those requirements present.

* **Honest accounting and limits.** Caveman distinguishes output-token and proxy input-token savings, warns that the skill itself costs roughly 1–1.5k input tokens each turn, and marks whole-session savings lower. Its compressor rejects input over the command limit rather than partially processing it; its README says originals are stored locally with recovery handles. These are good guardrails for Scopelet's short-output threshold and omission reporting. Source: [README benchmark/accounting caveat](https://github.com/JuliusBrussee/caveman/blob/15581d14007fd01fb3f132016741962f34936ca2/README.md), [CLI compression contract](https://github.com/JuliusBrussee/caveman/blob/15581d14007fd01fb3f132016741962f34936ca2/docs/technical/cli-reference.md#compress).

## Actionable Scopelet candidates

1. Keep the current byte threshold. A cheap preflight estimate that skips work when predicted savings cannot clear both 20% and 512 bytes is only an inference; adopt it only after false-negative evaluation on existing acceptance fixtures.
2. Preserve a stable prefix and append any tiny instruction/marker suffix, so repeated calls remain cache-friendly.
3. Keep Scopelet's existing JSON/JSONL and repeated-row coverage. Measure bytes and estimated tokens separately; never present `bytes/4` as provider usage. Future filters should add recovery references and explicit omission counts only where current acceptance requires them.
4. Track passthrough, parse failure, and below-threshold counts so filters can be removed when their own overhead dominates.
