# Automatic-mode pilot: Codex Luna

Date: 2026-09-09. Development implementation, not the published 0.1.3 binary.

## Method and scope

The primary campaign uses three isolated synthetic tasks, four repetitions and
four measured arms: native, automatic default, automatic caveman, and RTK.
Order is randomized with seed 20260912. Every session explicitly requests
`gpt-5.6-luna`, low effort, through Codex CLI 0.153.4. The returned stream does
not independently identify the serving model. No Claude Code model calls occur.

Each run gets a fresh workspace and isolated Codex configuration. The same task
prompt is used across arms without invoking a skill. Default/caveman install
Scopelet hooks; RTK gets its pinned upstream Codex awareness instructions.
All arms use the same isolated hook-trust bypass for this experiment. This does
not configure trust in the user's installation. Binaries and competitor
instructions are frozen and hashed before the campaign.

Headroom is **unmeasured**: the existing proxy adapter rejects Codex, and earlier
routing probes received zero requests. Its cells are absent measurements, not
zero-cost runs or native substitutes. This cannot establish superiority over
Headroom. RTK's instruction-based Codex integration differs from Scopelet's
hooks and incurs its own instruction overhead.

An external grader checks the final fixture independently. Every attempt,
failure and missing usage remains in the report. The headline metric is
provider-reported logical input plus output across the whole session, including
cached input; it is **not billed cost**. Cache counts and output counts are
retained separately. Final answer bytes are only a response-length diagnostic.
Four repetitions and three related fixtures do not establish a general result.

## Measurements

All **48/48 primary sessions pass**, with reported usage in every session.
Across this equally repeated three-task mix, default uses **23.4% fewer**
logical session tokens than native, caveman **21.5% fewer**, and RTK **2.4% fewer**.
These aggregate values depend on this task mix; they are not general savings guarantees.

| Task | Native mean | Default mean (change) | Caveman mean (change) | RTK mean (change) |
| --- | ---: | ---: | ---: | ---: |
| Small edit | 94,446 | 94,832 (+0.4%) | 87,848 (-7.0%) | 126,618 (+34.1%) |
| Noisy command | 166,312 | 98,618 (-40.7%) | 97,313 (-41.5%) | 117,197 (-29.5%) |
| JSONL aggregation | 84,132 | 70,708 (-16.0%) | 85,701 (+1.9%) | 92,858 (+10.4%) |

Each mean has four sessions. Standard deviations and every individual value are
in the [complete public report](../bench/results/luna-auto-2026-09-09.json).
For example, noisy-command standard deviations are 10,475 native, 8,158
default, 19,065 caveman and 19,032 RTK tokens. Tiny-edit default (+0.4%)
is within the observed variation; this study does not establish an improvement there.

Default and caveman each produce six observed automatic compact results in
their four noisy sessions. RTK has 144 recorded invocations across its twelve
sessions. No recovery calls or cache-path mentions appear in the typed shell
audit. Caveman final answers are not consistently shorter than default: on
the noisy task they average 202 versus 171 bytes. The separate preference
therefore remains optional rather than a promised optimization.

## Interpretation and actual coverage

The automatic compressor activates on the noisy-command task. The tiny-edit and
JSONL traces contain no automatic compression: their differences combine the
response instructions with model variability and cannot be credited to the
compressor. Caveman is a response preference, not a guarantee of lower session
usage. Use default for ordinary work and caveman when telegraphic answers suit
the task.

The compressor factors a common JSON schema without dropping values before
using selective views. Small outputs pass through unchanged; replacements must
save at least 512 bytes and 20%, including metadata. Selected evidence stays
whole, omitted units are counted, and original bytes remain recoverable.
These byte thresholds are heuristics, not tokenizer or billing measurements.
The rationale and upstream sources are in the
[optimization research](optimization-research-2026-09-09.md).

Typed completed-shell traces establish the visible automatic replacements.
The cache-path audit counts mentions of `.scopelet/cache/` or `scopelet-cache/`
in those results; a zero count alone does not prove absence of all cache
content ingestion. No claim is made about unobserved tool types.

## Final-binary validation

The primary binary remains frozen. Subsequent hardening adds simple eligible
`&&` chains, explicit interactive/background bypass, first/final diagnostic
anchors, native fallback when no whole evidence unit fits, exact installer
health checks, and a minimum-budget compact-run fix. These changes are checked
separately rather than silently pooled into the primary comparison.

Four additional Luna sessions use that final binary: default/caveman in ordinary
shell mode and default/caveman with experimental `code_mode` and `code_mode_only`
enabled. All four pass the external grader and each produces at least one
observed automatic compact result. The caveman shell trace also proves an
eligible `&&` chain was rewritten. Chains containing unsupported commands (for
example `git diff`) remain native. This validates integration, not a new
comparative savings estimate.

Evidence: [ordinary shell smoke](../bench/results/luna-final-shell-2026-09-09.json)
and [code-mode smoke](../bench/results/luna-final-code-mode-2026-09-09.json).
Primary plus validation consumes 52 sessions, within the 60-session ceiling.
The Claude adapter has offline contract tests only in this campaign.

The public JSON preserves usage, grades, hashes and typed trace audits. Raw
streams remain local under `bench/runs/luna-auto-20260909`; credentials are
removed before workspaces are archived. Later harness additions only expose
subset/code-mode switches and public export; the original harness hash remains
in the primary report.

tests, 60 offline harness tests, 8 launcher/release tests, packed skill validation,
codeindex/webindex adapters, offline bench and workflow syntax all pass. The
new release workflow has not run on GitHub and no release was published here.
