# Follow-up review, 2026-09-09

Two independent reviews (Claude Fable 5.1 and Claude Opus 5, high effort) read
the sources without running them and returned twelve findings, several
overlapping. This pass reproduced each one against the code, fixed what was
substantiated, and recorded what was rejected. Every claim below was checked
locally; nothing is carried over on the reviewers' word.

## Fixed, with regression tests

**Command capture was throttled to a fraction of pipe speed.** The reader slept
for the whole poll interval whenever a nonblocking pipe was momentarily empty,
so a stream advanced by roughly one pipe buffer per 10 ms while the child stayed
blocked on a full pipe. It now waits on the descriptor with `poll(2)` and the
same 10 ms bound, which keeps cancellation latency unchanged. Measured on this
host with `run --max-bytes 1024 -- sh -c 'head -c 20000000 /dev/zero | tr "\0" "a"'`:

| 20 MB of command output | Run 1 | Run 2 |
|---|---:|---:|
| Before | 48.2 s | 49.0 s |
| After | 4.5 s | 4.2 s |

The remaining time is dominated by hashing and record chunking, not capture. The
practical consequence of the old behavior was worse than slowness: a command
emitting a few hundred megabytes would hit the 120 s default timeout and be
reported as exit 124 regardless of its real runtime. `tests/process_contracts.rs`
now fails if 4 MB of output takes longer than three seconds.

**`clean` aborted on any file it did not write.** Surviving artifacts were
re-read as `artifact:<file name>`, and a name that is not 64 hex characters fails
the content-hash check. A `.DS_Store`, or a `.tmp` file left by a write that was
killed before persisting, made the whole command error out after it had already
deleted part of the cache, and it kept failing until the file was removed by
hand. Worse, once such a file aged past the threshold it was deleted as if it
were a cache item. Cleanup now treats only content-hash-named files as cache
items, leaves anything else alone, and reaps only its own aged `.tmp` files.

**Ultra could ship a record with no text at all.** Abridging kept lines only
while the next one fit in 1024 bytes, so a first line longer than that kept zero
lines: the record was emitted empty, with no end line, counted in
`shown_records` and consuming a page slot. Any minified asset or single-line JSON
log hit this. A too-long line is now cut on a character boundary and marked with
a new `text_truncated` field, the view carries a recovery note, and the exact
bytes stay in the record's blob. The field is optional and omitted when false, so
existing artifacts still deserialize.

**`expand --manifest` ignored `--max-bytes`.** The manifest printed the dataset
minus records with no budget at all, and it holds one snapshot per scanned file:
a wide scan can reach 20000 entries with absolute paths, on the order of
megabytes of JSON. This is the path the skill recommends precisely when no record
fits the budget, so it could flood the context it exists to protect. The manifest
now fills the budget with the snapshots that fit and reports `shown_snapshots`
against `total_snapshots` plus a truncation note.

**Paging an artifact re-persisted the whole dataset.** `render` always stored the
serialized dataset, so `expand artifact:X --offset N` re-serialized and re-hashed
the full result, then read the stored copy back to compare it byte for byte, once
per page. Paging now reuses the id it was given. Because storing also refreshed
the item's timestamp, expansion now explicitly touches the item instead, so a
result being paged still survives an age-based cleanup.

**`query --spec` silently dropped flags it could not apply.** `--count`,
`--context` and `--format` were accepted and discarded next to a spec, which
carries its own operations. They now conflict with `--spec`; defaults are
unaffected, so only an explicit flag is rejected.

**A note promised line numbers that some records do not have.** Reversed output
from a failed command claimed "line numbers preserve source order", but records
parsed from a top-level JSON array have no start line. The note now says line
numbers are preserved where a record has them.

## Substantiated but deliberately not changed

**`doctor` reports codeindex tested at 2.29.1 while its install string pins
2.30.0.** The inconsistency is real, and the symbols path hard-fails unless the
schema version is exactly 5, so a schema bump would break the `code` source for
anyone following the printed instruction while doctor still reports the adapter
available. Resolving it means running a real 2.30.0 adapter and changing a
recorded version, both outside this pass's mandate. It should be settled before
the next release.

**`expand blob:X` without a line range still writes a new artifact holding the
whole blob text**, up to 32 MiB, for a read-only operation. The artifact is what
makes the view pageable, so removing it needs a paging path for blob views rather
than a one-line change. Cache growth remains bounded by the 32 MiB per-item cap
and explicit cleanup.

## Rejected

**Binary and non-UTF-8 skips leaving `scan_complete` true is the documented
contract, not a bug.** `scan_complete` describes traversal of the defined scope;
binary files are excluded from that scope, every repository dataset carries a
note saying so, and the skips are counted in `skipped`. Read failures and
resource caps, which are not scope decisions, do set the scan incomplete.

**The claim that large JSON integers keep their decimal representation is
sound.** It depends on `serde_json`'s `arbitrary_precision` feature, which is
enabled in `Cargo.toml`, and `tests/independent.rs` covers it.

One reviewer's mechanism for the capture bug was inaccurate: reads are not capped
at one buffer per poll in general, since the loop only sleeps when the pipe is
empty. The observable effect was real and worse than estimated, so the finding
stands and the explanation above replaces theirs.

## Live measurement

Two small live campaigns were run against frozen release builds of the fixed
tree, each in its own output directory outside the published results. One task,
one run per cell, two agents, no raw transcripts or account metadata published.

The task is the noisy-command one: run a failing check that emits 1,200 distinct
progress lines, fix a worker-limit bug and rerun it. Baseline uses ordinary shell
and file tools; ultra uses the Scopelet skill in ultra mode. Agents were Codex
CLI 0.153.4 with GPT-5.6-Luna at low reasoning and Claude Code 2.1.263 with Haiku
4.5. Totals are logical input plus reported output tokens, the same accounting as
`docs/verification.md`.

Campaign B, binary `aad8c24e…`, the current build:

| Agent | Baseline | Ultra | Change |
|---|---:|---:|---:|
| Codex | 229,885 | 222,757 | −3.1% |
| Claude | 258,265 | 155,259 | −39.9% |

Campaign A, binary `e88d254b…`, the same fixes before the later flag, cleanup and
note changes:

| Agent | Baseline | Ultra | Change |
|---|---:|---:|---:|
| Codex | 165,718 | 141,153 | −14.8% |
| Claude | 257,009 | 126,993 | −50.6% |

All eight sessions passed their external grading, none timed out, and every ultra
session invoked Scopelet twice. Both campaigns move in the same direction as the
published noisy-command result.

The more useful result is the spread between them. These are identical
configurations run minutes apart, and Codex's baseline moved from 165,718 to
229,885 tokens while its saving moved from −14.8% to −3.1%. Single runs of this
task carry variation comparable to the effect being measured, which is the
central caveat of the published numbers and is reproduced here. Nothing in this
pass narrows it; a real estimate needs repeated sessions per cell.

## Limitations

The throughput numbers come from a single host, macOS ARM64, and depend on its
pipe buffer size. Nothing was measured on Linux in this pass. The capture layer
still marks drainage incomplete when a reader thread does not finish within
250 ms of the child exiting; under heavy parallel load that grace period can
expire even though every byte was read, which was observed once while running the
test suite with a new multi-megabyte test alongside it. That behavior predates
this pass and was left alone; the new throughput test was reduced to 4 MB so it
does not destabilize its neighbors.

Each campaign froze and hashed its binary before starting. Campaign B's build
predates one later edit to `src/store.rs`, a pure extraction of the shared
temporary-file branch in cleanup with no behavior change, covered by the same
tests. Versions, tags, agent user settings and workflows were not touched, and
nothing was committed.
